Three distinct mechanisms

Mechanism Trigger Transformation
Full conversation compaction Automatic threshold, manual request, or overflow recovery Summarize history; retain originals as agent-invisible; add summary/continuation.
Tool-pair summarization Eligible old tool calls exceed cutoff plus batch Replace selected model-visible pairs with smaller summaries, preserving recent work.
CompactingProvider wrapper ContextLengthExceeded at the provider call boundary Retry once with a summary standing in for messages.

These mechanisms share summarization primitives but are not equivalent. Full application compaction handles visibility and session usage; the standalone provider wrapper has no access to Goose’s transcript database. Self-managed providers bypass Goose-side automatic compaction and tool-pair summarization.

Threshold specification

Automatic compaction uses current tokens divided by the provider-derived context limit. It prefers session usage.total_tokens when available; otherwise it estimates agent-visible messages. A valid automatic threshold is strictly between 0 and 1, and compaction triggers on a strict greater-than comparison. The default is 0.8. Values ≤0 or ≥1 disable that automatic trigger; this does not prove every overflow-recovery path is disabled.

At a 128000-token context limit, 102400 tokens equals 0.8 and does not satisfy the strict trigger; 102401 does. Token estimation for this path is not an exact accounting of every provider wire overhead or tool-schema expansion. An oversized system prompt can still fail when message history is short.

Full-history compaction step by step

  1. For automatic compaction, locate the latest eligible agent-visible user text message, excluding turn-context events and tool-bearing messages.
  2. Summarize the conversation through the provider abstraction.
  3. Copy originals with agent visibility turned off, retaining their user visibility metadata.
  4. Append an agent-only summary and an assistant continuation, choosing continuation text for manual compaction, recent user kickoff, or mid-tool-loop recovery.
  5. Append the preserved user text when present. Carry the current turn-context event with a fresh identity and a timestamp that preserves appended order.
  6. Estimate retained context tokens separately from the summarizer’s billable usage and return both.

The preserved message is a text-only projection; images are not blindly copied by that branch. Timestamps matter because storage reload orders messages by creation time. Copying a context event with its old timestamp would put the newly appended event back into the wrong part of history.

Summarizer overflow recovery

The standalone summarizer tries removal percentages [0,10,20,50,100]. It formats selected history into a system prompt and submits a short user request. Only ContextLengthExceeded advances to another removal attempt. Other provider errors return immediately. A history with no tool-response messages fails after its first overflow because there is nothing the algorithm can remove.

Removal works over message indices containing tool responses and expands from the middle. This is a positional heuristic intended to retain beginnings and recent context. It drops entire response-bearing messages, which can also contain other blocks; it is not a token-level truncator or a semantic relevance ranking. For even counts the center alternation is straightforward. The implementation’s boundary checks can under-remove for odd counts: five response messages at the 100% attempt omit four, leaving the far-right one. The final error text says “all tool responses,” but readers should distinguish that label from the exact index-selection behavior.

On success, the summary takes User role. Token estimates are filled from the raw model output before a structured summary is rendered, preserving billable output accounting. A schema-ignoring model or invalid custom rendering keeps the raw text rather than discarding the whole summary.

Tool-pair cutoff and batching

The cutoff is clamp(floor(3 × floor(context_limit × threshold) / 20000), 10, 500). Here threshold values in (0,1] are accepted; invalid values fall back to 0.8. This differs from the full automatic trigger, where threshold=1 disables compaction. For context=128000 and threshold=0.8, the cutoff is 15.

The algorithm gathers agent-visible tool-request IDs in order, subtracts protect_last_n using saturating arithmetic, and triggers only when eligible calls exceed cutoff+10. It selects the oldest ten IDs. With cutoff=15 and no protected calls, 25 calls do not trigger but 26 do. With five protected calls, the same trigger requires at least 31. A pair summarization requires both an agent-visible request and response.

Structured summaries and practical limits

StructuredSummary includes user intent, technical concepts, file activities, errors/fixes, problem-solving steps, user messages, pending tasks, current work, and next step. Its lists are intended to be ordered by importance. Lenient deserializers stringify unexpected objects or numbers; unknown top-level fields remain available to custom rendering. This tolerance is appropriate at a model-output boundary and avoids rejecting useful context for one schema deviation.

Summarization is lossy and adds inference cost. Protecting the active turn and retaining the original transcript mitigates that cost but cannot prove that every earlier constraint survives the summary. Measuring retained tokens separately from cumulative usage prevents “the compacted prompt size” from being confused with “all tokens paid for so far.”
