Verification boundaries for this documentation change

The change adds static HTML documentation, styles, search/navigation JavaScript, a provenance manifest, and a verification script. Structural checks verify local links and fragments, balanced HTML, page landmarks, exact excerpts, hashes of referenced source files, and API inventory uniqueness. Browser checks, when available, exercise page loading and navigation/search at a real local HTTP boundary. The recorded verification report states what actually ran.

Goose provider inference, third-party MCP APIs, remote ACP harnesses, local model inference, and roaming are not exercised merely by rendering this wiki. No mocks, replay recordings, or health checks are counted as those integrations. Their live behavior remains unverified by this documentation task. Revalidate the affected real boundary when API, runtime, credentials, or external service behavior changes.

See verification.json for executed checks and manifest.json for source and excerpt provenance.

Maintenance without erasing the snapshot

This timestamp directory is a source-grounded edition. After code changes, create a new timestamped edition or explicitly update the provenance and descriptions together. Do not silently point line links to main: readers would lose the ability to inspect the code that justified the prose. Reuse valid integration evidence only while the relevant environment and service contracts remain unchanged.

A machine-generated inventory supports completeness but does not replace semantic review. In particular, compare both loops during migration, validate enum serialization against the exact attributes, inspect feature gates before recommending a command, and distinguish declared methods from enabled handlers.
