1. Tiny kernel, durable effects

Pattern: ports and adapters plus an ordered chain of responsibility. The kernel’s run loop reloads, selects, applies, and yields; session-specific persistence lives behind traits. Why it stands out: an application can replace SQL storage or define custom effects without copying the agent scheduler. Limit: restartable decisions still require operation authors to persist enough evidence and guarantee progress.

Source: crates/goose-agent/src/machine.rs:1 · crates/goose/src/agents/state_machine/session.rs:1

2. The retry counter lives on the survivor

Pattern: attach durable state to the record that survives a transformation. Resetting a failed recipe attempt keeps the kickoff and drops later history, so the attempt count lives on that kickoff. Why it stands out: it avoids a subtle infinite-retry bug where the counter vanishes during the very reset it governs. Limit: custom history transformations must preserve the same metadata invariant.

Source: crates/goose/src/agents/state_machine/ops_retry.rs:76

3. Persist before publishing an answerable request

Pattern: make durable state visible before emitting a control message. Why it stands out: user confirmation can arrive in milliseconds, so ordering the database write first removes a real race rather than relying on UI slowness. Limit: this selected ordering is not a universal outbox protocol for all events.

Source: crates/goose/src/agents/state_machine/session.rs:120

4. Restrictive findings never become permissive by accident

Pattern: monotonic restriction aggregation. Deny dominates; approval can strengthen an allowed request; Allow cannot undo either. Why it stands out: independent security, permission, and repetition checks compose without requiring each to understand every other inspector. Limit: the coordinator continues after inspector errors, so failure policy must be considered independently from decision policy.

Source: crates/goose/src/tool_inspection.rs:170

5. Signatures define reasoning boundaries

Pattern: protocol-aware incremental assembly. A signed block is immutable evidence, so its boundary survives visual text concatenation. Why it stands out: a few conditions prevent later provider requests from rejecting a reasoning transcript that looked harmless to a human. Limit: this invariant must remain consistent in both Conversation::push and collect_stream.

Source: crates/goose-provider-types/src/conversation.rs:1 · crates/goose-provider-types/src/base.rs:1

6. Cache installation checks the world did not change

Pattern: optimistic generation validation around asynchronous fetch. Why it stands out: network discovery happens outside the mutex, while a version check prevents stale results from poisoning the shared cache. Limit: it permits duplicate misses and does not revoke the already returned fetched value.

Source: crates/goose/src/agents/extension_manager/mod.rs:749

7. Compaction retains the human record

Pattern: independent projections over one durable history. Why it stands out: a bounded model request need not erase evidence from the user’s transcript. Limit: summaries remain lossy, and both message flags and content audiences must be honored.

Source: crates/goose/src/context_mgmt/mod.rs:1 · crates/goose-provider-types/src/conversation.rs:1

8. Reserve the writer before reading

Pattern: SQLite read-modify-write with BEGIN IMMEDIATE. Why it stands out: it solves lock-upgrade contention at the point where the transaction enters rather than scattering retries around later SQL. Limit: long write transactions still reduce concurrent writer throughput.

Source: crates/goose/src/session/session_manager.rs:3855

9. Heap-box a large async dispatch chain

Pattern: intentional async future allocation at a stack pressure boundary. The ACP dispatch implementation notes that its generated matching chain creates an approximately 85 KiB state machine and uses Box::pin. Why it stands out: the allocation is justified by worker-stack safety instead of being an unexplained abstraction. Initialization stays inline so pipelined new-session work cannot race before capabilities are established. Limit: the size comment is source evidence, not a fresh measurement in this wiki.

Source: crates/goose/src/acp/server/dispatch.rs:1

10. Adapt platform constraints at trait boundaries

Pattern: portability policy in MaybeSend/MaybeSync and target-specific timers. Why it stands out: native hosts retain thread-safe contracts while WASM can hold JavaScript handles and await host promises without a Tokio runtime. Limit: sync tools execute inline on WASM and cannot be interrupted once started.

Source: crates/goose-agent/README.md:1 · crates/goose-provider-types/src/maybe_send.rs:1 · crates/goose-provider-types/src/retry.rs:1
