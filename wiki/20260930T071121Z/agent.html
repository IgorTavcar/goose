The generic transition algorithm

  1. Load a session from the runtime. A missing conversation is an error when stepping.
  2. Walk the ordered steps. After cancellation, skip normal run methods and allow each cancel hook to rewrite a not-applicable result.
  3. For an inference step, first ask whether it applies. If so, collect tools, prompt parts, and MOIM parts from every step, rejecting duplicate tool names.
  4. Await the operation, run its cancellation hook if cancellation occurred, and select the first Applied result.
  5. Assign missing message IDs, persist the effects, and reload before the next pass. Stop on yield or when no step applies.

No applicable step means quiescence, which is different from an exception. yielded() produces an Applied result with no effects and explicitly returns control to the caller. Applied with empty effects and no yield can spin indefinitely if its applicability never changes; operation authors must establish progress themselves.

Concrete Goose operation order

Order Operation Purpose
1 Entry hook; slash command Lifecycle and commands precede normal work.
2 Steer; max turns; bang shell Accept steering, enforce budget, handle direct shell requests.
3 Compaction; tool-pair compaction Reduce context when applicable; full compaction is omitted for self-managed providers.
4 Tool approval Inspect advertised calls and persist approval/executability decisions.
5 Doctor; project; skills; recipe Handle specialized commands and capabilities.
6 Tool execution; unknown tool Dispatch valid extension calls and resolve remaining unknown requests.
7 Retry; stop hook; exit on error Check completion, enforce lifecycle policy, stop on terminal errors.
8 Inference Reach the model after higher-priority work declines.

Status is included in slash-command handlers rather than as a separate normal operation. Compaction is conditionally inserted. Tool-pair summarization is disabled for providers that manage their own context. This table is the construction order at the snapshot, not a timeless plugin priority registry.

History predicates are the state vocabulary

messages_since_kickoff finds the last user-role, user-visible message that is not a tool response. It returns the suffix starting there and errors if none exists. This makes tool results encoded with User role distinct from a genuine new user request. assistant_turn_count counts blocks of consecutive assistant-role messages, so streaming fragments do not automatically consume many autonomous turns. ends_turn requires a trailing assistant without errors, tool requests, or ActionRequired content.

The turn-budget operation stops when the suffix’s assistant-block count is at least max_turns. Its MOIM reminder starts once at least half the budget is consumed; max_turns=0 suppresses the reminder but does not disable the stopping comparison. Ordinary completion and budget exhaustion therefore have different predicates.

Effects are data, persistence is an adapter

The generic conversation effects append a message, replace a conversation, patch tool-request metadata, or change visibility. Goose adds recipe state, extension state, compaction with usage, and usage recording. The machine normalizes IDs before handing effects to the runtime. Its abstraction permits a caller to use step and apply separately or run the whole loop.

Goose’s effect handler performs a persistence pass over the list and then emits selected notifications. Approval requests are published after persistence because a client can respond immediately. This is a carefully chosen race boundary. It is not one transaction covering every effect, nor a blanket rule that every streamed token is persisted before presentation.

Inference preparation and event identity

The inference runner prepares a system prompt, advertised tools, and optional additional messages. It repairs model-visible conversation structure and merges messages for the request. Streamed text and tool calls accumulate into durable effects; usage is recorded separately. Repeated reasoning copied into a tool-call chunk is removed when it already exists in the current accumulator.

The Agent reply wrapper is the shared live-event identity boundary. A producer intentionally streaming several events for one logical message must set its shared ID before that boundary. Consumers should correlate updates by identity rather than treating every event as a new message.

Cancellation and the legacy comparison

Cancellation is cooperative. The machine checks before operations and provides cancel hooks after execution. Applied results observed after cancellation yield to the client. Tool discovery uses a biased select so cancellation can win before continuing discovery. Arbitrary operation futures are not universally aborted by the kernel; their implementation owns interruption and cleanup.

The legacy loop carries local turns and compaction attempt counters inside its streaming loop. The newer path moves many decisions into independently applicable operations and history metadata. The legacy context-overflow branch refuses to continue after repeated recovery overflow. Both paths still expose AgentEvent streams and the application’s session/tool machinery.
