ACP transport specification

goose acp serves stdio; goose serve exposes HTTP/WebSocket ACP. The bare router is documented as POST/GET/DELETE on /acp. Standalone auxiliary GET /health and /status return “ok.” The serve command defaults to 127.0.0.1:3284, with optional TLS and configured authorization/origin behavior. This API uses JSON-RPC methods over ACP rather than a REST endpoint per agent operation.

Initialize establishes protocol and client capabilities before pipelined new-session operations. Session new/load/list/fork, prompt, cancellation, and session configuration dispatch map to typed ACP requests. Prompt progress comes through notifications before the final response. Agent→client permission and elicitation requests require replies; they are not ordinary fire-and-forget messages.

An exact Goose request envelope

The following is an illustrative JSON-RPC request using the inspected GetToolsRequest fields. The session must already exist and be available to the connection. request id 7 is chosen for the example; the result contains ToolListItem records with inputSchema, optional outputSchema, name, description, parameter names, and permission.

{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "_goose/unstable/tools/list",
  "params": {
    "sessionId": "YOUR_SESSION_ID",
    "extensionName": "developer"
  }
}

The direct custom tools/call request takes sessionId, extensionName, name, and arguments. Its response exposes content, optional structuredContent, isError, and optional _meta. Do not confuse this direct-call envelope with the model’s internal ToolRequest, which has different correlation and approval machinery.

Server-to-client extensions and notifications

The server can request recipe values through _goose/unstable/session/recipe/request-params, with RequestRecipeParams and RecipeParamsResponse. Its declaration is a method constant collected by agent_request_schemas, so it belongs to the reverse direction rather than the client-to-agent table below.

The _goose/unstable/session/update notification contains sessionId and update. Its discriminant is sessionUpdate with snake_case values usage_update, status_message, message_usage, and live_voice_interaction_ended, even though surrounding fields are camelCase. Device-code authentication uses _goose/unstable/providers/authentication/device-code with providerId, userCode, verificationUri, and expiresIn. Capability support controls delivery of Goose custom notifications.

Rust operation and runtime contracts

Contract Implementer responsibility
Operation<S,E> name; optional run/cancel/commands; optional tools, prompt_parts, moim_parts contributions.
Inference<S,E> applies predicate and infer using collected input.
MachineSession id and conversation access.
SessionLoader<S> Load fresh session state by ID.
EffectHandler<S,E> Persist effects with host semantics.
MachineEffect Assign stable IDs where applicable.
ToolProvider / SyncTool / AsyncTool Supply stable names/schemas and current-session handlers; dynamic tools are queried before inference and execution.

OperationResult is NotApplicable or Applied(StepResult). StepResult contains effects, selected-step name, and yield_to_client. The machine reloads between passes. The provider stream contract and its error categories are described on the providers page.

UniFFI binding contract

The bindings feature exports provider constructors and typed message/tool/model structures. Provider exposes name, supported_features, context_limit, list_models, stream, complete, and compact. ProviderStream::next_chunk returns an optional StreamChunk or a typed error. A None terminates consumption. The SDK exposes typed lifecycle observability events with one end event per request and no delivery after a hook is cleared; streamed response capture is not buffered into responseJson.

Python package name is goose-sdk and import namespace is goose. Kotlin uses io.github.aaif_goose; the Maven artifact is io.github.aaif-goose:gdk. These names are checked-in packaging contracts, not verification of the latest registry publication. The source snapshot controls this wiki’s examples.
