The required provider interface

A provider supplies its name and streaming implementation. Native traits use Send/Sync through MaybeSend/MaybeSync; WASM traits relax those bounds. Model configuration, system prompt, messages, and MCP tools are distinct inputs. The stream yields Result tuples containing optional message and optional usage; either may arrive without the other. Text can be incremental, while tool calls must be assembled before emission.

The default complete method collects the stream. Other defaults cover model inventory, context limits, retry policy, resume, provider session identity, and permission routing. The small contract crate supports implementing a provider without depending on Goose’s CLI or desktop.

Native and declarative adapters

Native modules implement vendor-specific protocols: Anthropic, OpenAI, Google, Databricks, Azure Foundry, Snowflake, Ollama, and others in the checked-in provider tree. Declarative definitions package configuration into JSON and select an OpenAI, Ollama, or Anthropic engine. A compatible service can therefore reuse conversion, auth, retry, and streaming logic instead of growing a duplicate adapter.

Definitions include model metadata and environment configuration. The configuration’s brand is not a new transport protocol. When diagnosing failures, inspect the selected engine, base URL, request parameters, and HTTP response mapping. Provider wrappers in the Goose application add application-specific registry and ACP behavior on top of the released provider crate.

Canonical metadata is a snapshot plus live discovery

The canonical registry maps provider-specific names to canonical provider/model IDs and supplies context limits, capabilities, and per-token costs. ModelInfo also carries optional resolved model, cache control support, reasoning preservation format, and request parameters. Metadata is not a guarantee that a remote service still exposes an ID. The repository has a builder that fetches metadata and checks mapping changes, but this wiki records the checked-in state only.

The recommendation logic retains unknown future models rather than assuming absence from the bundled registry means unusable. Separately, toolshim settings affect whether tool-less models are kept. Treat inventory, recommendation, and canonical mapping as distinct operations when integrating a settings UI.

Retry policy in detail

Transient categories include rate limiting, server errors, and network errors. RequestFailed is also retried by default, unless transient_only is enabled or the failure matches a known permanent reasoning/signature constraint. The default policy allows three retries after the original request. Authentication refresh in ProviderRetry is a separate one-time attempt and does not consume the transient retry counter.

For retry number a≥1, the base delay is initial_ms × multiplier^(a−1), capped at max_interval_ms, then multiplied by uniform jitter in [0.8,1.2). Consequently the final delay can exceed the nominal cap by almost 20%. A provider-supplied rate-limit retry_delay takes precedence. Default values are 1000 ms, multiplier 2, and cap 30000 ms. WASM waits use the host timer.

This retry surrounds operations that establish or perform a request. It does not prove safe replay after arbitrary partial streamed output or tool side effects. Recipe retries use separate settings and success checks, covered on the recipes page.

Provider-managed state and context

manages_own_context() tells Goose to avoid duplicating context management performed by a separate harness. ACP providers can expose provider session identity, resume behavior, model/mode changes, and permission routing. The application must keep a session’s model selection scoped to that provider context rather than leaking it into another conversation.

CompactingProvider also reports self-managed context. It catches ContextLengthExceeded returned when creating a stream or running complete, summarizes history, and retries once. It does not intercept every error emitted later while consuming an already-open stream. This narrower boundary is easy to miss when wrapping a streaming API.

Local inference and cross-language use

On-device inference is optional and has accelerator feature gates. The model runtime and download manager are separate crates so model lifecycle and transfer progress need not be tied to the application. goose-sdk adds UniFFI constructors, streaming reads, completions, and compaction for Python and Kotlin. Its ProviderModelConfig and ProviderMessage are binding types with explicit conversions; they are not automatically identical to the Rust internal structs.
