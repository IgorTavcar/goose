Shared runtime, different experiences

The CLI main enters command parsing and session machinery in goose-cli. The desktop main process manages windows, backend processes, secrets, readiness, and IPC. React renders a client-side session view. Both ultimately use the same Rust agent facilities, so the interfaces need not implement their own model/tool loop.

Desktop obtains an ACP URL from the preload-exposed Electron API and creates a WebSocket stream. It composes the standard ACP SDK with Goose extension methods from @aaif/goose-acp-client. The TypeScript package deliberately leaves executable resolution and process lifecycle to its caller; the separate launcher package handles launching for other consumers.

Connection single flight and generations

acpConnection keeps currentConnection and pendingConnection separately. Concurrent callers reuse the pending promise, avoiding several initialization attempts for one backend. Recovery increments a generation, clears current/pending state, closes the old connection, and begins another attempt. Completion handlers only update recovery state when their generation remains current.

This is a lightweight defense against stale async work: an older attempt must not overwrite a newer connection after system resume or reconnection. Initialization has a 10000 ms timeout; reconnection delay starts at 500 ms and has a 30000 ms cap. Backend-exited errors are distinguished from reconnectable failures. The generation is a lifecycle version, not a session ID.

Session store and notification adapters

The chat store keeps a map per session and listeners per session, with adapters that convert standard ACP and Goose notifications into UI messages, tool events, permissions, elicitations, token state, and progress. Prompt attempt IDs, active run IDs, and cancellation restoration state guard transitions when replies arrive after a newer action.

During history replay, reading a deep clone of the growing message array for each notification would produce cumulative quadratic work. The store reuses the last published snapshot while LoadingConversation is active. This is a targeted optimization at the read path rather than an assumption that all live state can be reused without invalidation.

Backend leases and process privileges

The desktop startup path can own a launched serve process or use an external backend. GooseServeLeaseRegistry centralizes backend ownership across windows, so closing one consumer is not equivalent to blindly killing a process still used by another. Startup readiness and TLS fingerprint checks provide evidence that the selected endpoint is the intended backend.

BrowserWindow configurations disable Node integration and enable context isolation. The preload layer exposes an intentional IPC API instead of granting raw Node primitives to React. File access and external URL opening have dedicated helpers; these are important review surfaces whenever a rendered tool result or link can ask the application to open local or remote content.
